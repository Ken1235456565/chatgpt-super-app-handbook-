# Incremental Roadmap

## Phase 0 — Governance

Deliver:

- project charter;
- content architecture and integration map;
- editorial and site standards;
- acceptance criteria;
- project-local maintenance skill;
- status record.

Exit gate: the rules are internally consistent and the skill validates.

## Phase 1 — Source and content audit

Audit the current generated Markdown against the Google document.

- Confirm all 14 chapter boundaries.
- Inventory requested overview topics and mark each as present, partial, or missing.
- Identify duplicated material and stale technical claims.
- Produce an issue list without redesigning the site.

Exit gate: every requested topic has an owner and disposition.

## Phase 2 — Reader foundation

Refine only:

- homepage path selection;
- Chapters 1–3;
- shared navigation and baseline metadata.

Exit gate: a beginner can understand the application and locate a first task.

## Phase 3 — Working method

Refine Chapters 4–5:

- clear tasks;
- files and context;
- planning, progress, subagents, handoffs;
- review;
- first small project;
- beginner, creator, developer, and team paths.

Exit gate: each path produces a reviewable first outcome.

## Phase 4 — Developer system

Refine Chapter 6 in bounded groups:

1. AGENTS.md and project configuration.
2. CLI and profiles.
3. IDE, GitHub, worktrees, and cloud.
4. Automation, SDK, webhooks, and reference material.
5. Troubleshooting.

Exit gate: commands and current product claims are verified against official sources.

## Phase 5 — Artifact workflows

Refine Chapters 7–12, one chapter at a time. Begin with Chapter 7 file types and artifact acceptance, then writing, research, productivity, creativity, and business.

Exit gate: each chapter includes a workflow, example, verification, and handoff.

## Phase 6 — Trust and future

Refine Chapters 13–14:

- permissions and sandboxes;
- Plugin and MCP risk;
- prompt injection;
- sensitive context;
- verification and troubleshooting;
- durable future-facing conclusions.

Exit gate: security boundaries are precise and no speculative statement is presented as current fact.

## Phase 7 — Release readiness

- Complete cross-link and navigation review.
- Validate responsive and accessible behavior.
- Recheck volatile claims.
- Confirm GitHub repository layout and Vercel project root.
- Produce a release candidate and request deployment authorization.

Exit gate: all criteria in `ACCEPTANCE.md` pass.
